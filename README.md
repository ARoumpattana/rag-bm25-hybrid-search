# rag-bm25-hybrid-search

A personal portfolio side project demonstrating a production-grade Hybrid Search and RAG (Retrieval-Augmented Generation) pipeline built with .NET 8, tailored for automated cargo and logistics classification via a terminal-based CLI interface.

---

## Part 1: Business Context (Why this project exists)

### The Problem in Logistics
In international shipping, customs clearance, and freight forwarding, cargo descriptions are rarely clean. When a shipper or port operator inputs item details into a system, the text arrives as a messy, unstructured string full of system codes, port identifiers, dates, and tracking numbers. 

For example:
    XYZ999::IMPORT:THLCH:FRESH LONGAN GRADE A PACKING:260825::CONTAINER-40FT

If you try to classify or search this using traditional database queries (`WHERE description LIKE '%LONGAN%'`), it will fail if there's a typo, or if the keyword is formatted differently. Furthermore, companies need these raw descriptions mapped into standardized, clean categories (and translated into professional Thai terminology) for reporting and compliance.

### The Solution
This application acts as an intelligent classification pipeline. It ingests messy logistics strings, strips away the noise, matches them against a pre-defined list of master keywords using both exact keyword matching and semantic AI, and outputs a clean, standardized classification:

    Final Answer: 
        ลำไยสด (FRESH LONGAN)

---

## Part 2: Technical Architecture & Pipeline Flow

The system processes a user input through a multi-layered retrieval and generation strategy:

1. **Lexical Search (Lucene.NET BM25):** 
   - Scans the input text for exact or partial keyword matches using the industry-standard BM25 scoring algorithm. Excellent for catching exact product terms embedded inside noisy strings.
2. **Semantic Vector Search (Ollama Embeddings & Cosine Similarity):** 
   - Sends the input text to a local embedding model (`qwen3-embedding:8b`) to generate vector representations. It compares them against cached category vectors using `System.Numerics.Tensors` (Cosine Similarity) to capture conceptual meaning even if exact words differ.
3. **Re-Ranking via Reciprocal Rank Fusion (RRF):** 
   - Combines the ranked lists from both BM25 and Vector Search using the `drittich.ReciprocalRankFusion` library to produce a single, highly accurate candidate list.
4. **LLM Decision & Translation (Ollama Local LLM):** 
   - Sends the top candidates along with the original input to a local decision model (`gemma4:e2b`) using a strict Few-Shot Prompt. The LLM selects the best match, filters out noise, and translates it into natural professional Thai.
5. **Smart Fallback Handling:** 
   - If lexical search fails, it falls back to vector search. If vector search fails, it falls back to lexical search. If both fail, it gracefully reports no match.

## Part 4: Configuration (`appsettings.json`)

The application is fully environment-agnostic. All paths are relative, allowing it to run on Windows, macOS, or Linux without path modification.

    {
      "AppSettings" : {
        "RegisterData": true,
        "FilePathEmbeddedJson": "Data/VectorCache/embeddings.json",
        "FilePathFullTextSearch": "Data/LuceneIndex"
      },
      "AppConfig": {
        "UrlAPI": "http://localhost:11434",
        "EmbeddedModel": "qwen3-embedding:8b",
        "DecisionModel": "gemma4:e2b"
      },
      "Logging": {
        "LogLevel": {
          "Default": "Information",
          "Microsoft.Hosting.Lifetime": "Information"
        }
      }
    }

*(Note: Set `RegisterData` to `false` after the first run to skip re-indexing and speed up startup time.)*

## Part 5: Getting Started

### Prerequisites
1. .NET 8 SDK or higher.
2. Ollama installed and running locally (`http://localhost:11434`).
3. Required local models pulled:

    ollama pull qwen3-embedding:8b
    ollama pull gemma4:e2b

### Execution
1. Clone the repository:

    git clone https://github.com/your-username/rag-bm25-hybrid-search.git
    cd rag-bm25-hybrid-search

2. Run the application:

    dotnet run

## Part 7: Production Considerations

While this application uses a terminal-based CLI and mocks master data using an in-memory `List`, a real-world enterprise implementation would typically involve:

- **API Service Integration:** Exposing the classification pipeline as a Web API service so other business applications can consume it via HTTP requests instead of a terminal interface.
- **Database-Driven Ground Truth:** Replacing the hardcoded `List` mock with dynamic ground truth data loaded from a SQL database for embedding and matching.
